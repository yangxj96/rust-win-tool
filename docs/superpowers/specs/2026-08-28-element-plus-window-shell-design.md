# Element Plus 风格 GPUI 窗口壳层设计

## 目标

将现有 GPUI 界面从“顶部页面标签 + 底部提示栏”调整为现代桌面管理工具布局：左侧固定宽度导航，右侧内容区，自绘无边框标题栏，并保持现有服务管理、系统信息、Navicat 清理、语言切换、主题切换和配置兼容功能不变。

本次工作只重构窗口壳层、视觉 token 和页面布局，不增加当前五个未实现系统工具的功能，也不恢复全局键盘快捷键。

## 已确认约束

- 左侧导航栏固定宽度，不随右侧内容滚动。
- 标题栏完全使用 GPUI 绘制，隐藏 Windows 默认标题栏。
- 窗口拖拽、最小化、最大化/还原和关闭由 GPUI 的窗口控制区域接入 Windows 原生窗口行为。
- 页面导航和业务操作继续使用可见鼠标控件。
- 添加服务搜索框保留文字输入和退格编辑能力。
- `config/managed_services.json`、`config/settings.json` 的路径、字段名和序列化值保持不变。
- 继续使用 `gpui = "=0.2.2"`，不引入第三方 UI 组件库。

## 当前基线

- 根实体是 `MainWindow`，持有 `Entity<AppState>`。
- 当前布局由顶部标题/Tab、右侧页面内容和底部快捷键提示组成。
- `WindowOptions` 只配置窗口尺寸和最小尺寸，没有自绘标题栏配置。
- `components.rs` 已提供基础按钮、Tab 和搜索框，但颜色 token 仍偏向当前页面实现，缺少侧栏、标题栏、卡片和状态徽章语义。
- 所有业务操作已经通过 GPUI 后台任务执行，本次不改变后台任务边界。

## 方案比较

### 方案 A：GPUI 客户端自绘标题栏 + 原生命中测试（采用）

通过 `TitlebarOptions { appears_transparent: true }` 隐藏默认 Windows 标题栏，在 GPUI 内容树中绘制标题栏。标题栏拖拽区使用 `WindowControlArea::Drag`，窗口按钮分别使用 `Min`、`Max`、`Close`。GPUI 0.2.2 的 Windows 平台会将这些区域转换为原生 hit-test 结果，因此 Windows 的贴靠、最大化边界和关闭语义继续由系统处理。

优点是视觉和行为都统一，最大化/还原、窗口拖动不需要自行维护鼠标状态；缺点是需要在标题栏布局中避开按钮命中区域，并在无边框窗口下验证边缘缩放行为。

### 方案 B：普通 GPUI 点击回调调用窗口 API

用普通 `on_click` 回调调用 `Window::minimize_window`、`zoom_window` 等 API，并自行处理标题栏拖拽。实现看起来直观，但拖拽、双击标题栏、Windows 贴靠和最大化状态同步都需要额外维护，容易出现和系统行为不一致的问题。

### 方案 C：保留系统标题栏，仅改造应用内容区

只实现左侧导航和 Element Plus 风格内容区，不隐藏系统标题栏。风险最低，但不满足“标题栏完全无边框、由 GPUI 接管”的约束，因此不采用。

## 窗口结构

窗口从上到下、从左到右组织为：

```text
MainWindow
└── vertical shell
    ├── custom titlebar (48px)
    │   ├── app mark + title
    │   ├── draggable empty area
    │   └── Min / Max / Close native control areas
    └── horizontal workspace
        ├── sidebar (220px, fixed)
        │   ├── app identity
        │   └── four navigation items
        └── content (flexible)
            ├── page header
            └── page body/card content
```

### 自绘标题栏

- 窗口选项设置 `titlebar.appears_transparent = true`，同时保持 `is_movable = true`、`is_resizable = true`、`is_minimizable = true`。
- 标题栏高度固定为 48px，绘制应用图标/字标、应用标题和右侧三个窗口按钮。
- 除按钮外的标题栏空白区域标记为 `WindowControlArea::Drag`。
- 最小化按钮标记为 `WindowControlArea::Min`，最大化按钮标记为 `WindowControlArea::Max`，关闭按钮标记为 `WindowControlArea::Close`；不通过业务状态模拟窗口关闭。
- 最大化按钮图形根据渲染时的 `Window::is_maximized()` 显示最大化或还原状态。
- 控件顺序、间距和 hover 状态遵循 Windows 标题栏习惯，关闭按钮使用危险色 hover 背景。

### 左侧导航

- 宽度固定为 220px，背景与右侧内容区形成轻微层级差，以 1px 分隔线分隔。
- 顶部显示应用标识和简短副标题；副标题不参与业务逻辑。
- 导航项使用图标占位、文字、整行可点击区域和 active 状态。
- 当前页面使用浅蓝背景、主色文字和左侧 3px accent 条；未选中项使用普通文字和 hover 背景。
- 导航栏不包含滚动容器，四个页面始终完整可见。

### 右侧内容区

- 内容区使用 `flex_1`，背景采用 Element Plus 风格的浅灰或深色主题背景。
- 页面顶部保留页面标题、当前页面说明和必要的主操作按钮。
- 服务列表、系统信息、脚本结果和设置项使用白色/深色表面卡片，不再依赖底部快捷键提示。
- 服务页的操作按钮集中在页面 header/toolbar 中；服务列表卡片内部保持行选择和状态列。
- 工具页、脚本页和设置页沿用现有数据与事件，仅调整卡片、间距、状态色和鼠标入口。
- 详情页使用内容区内的返回按钮，不依赖 Esc。

## 视觉系统

将 `ThemeColors` 扩展为 UI 语义 token，而不是在页面中散落颜色值。至少包括：

| Token | 浅色主题 | 深色主题 | 用途 |
|---|---:|---:|---|
| `primary` | `#409EFF` | `#66B1FF` | 主按钮、active 导航、链接 |
| `success` | `#67C23A` | `#85CE61` | 运行中状态 |
| `warning` | `#E6A23C` | `#EBB563` | 加载/进行中状态 |
| `danger` | `#F56C6C` | `#F78989` | 错误、停止状态、关闭 hover |
| `bg_window` | `#F5F7FA` | `#0F172A` | 根窗口背景 |
| `bg_sidebar` | `#FFFFFF` | `#111827` | 左侧导航背景 |
| `bg_surface` | `#FFFFFF` | `#1F2937` | 卡片和行表面 |
| `bg_select` | `#ECF5FF` | `#1E3A5F` | active/selected 表面 |
| `border` | `#E4E7ED` | `#334155` | 分隔线和输入边框 |
| `fg_default` | `#303133` | `#E5E7EB` | 主文字 |
| `inactive` | `#909399` | `#94A3B8` | 次要文字 |

统一使用小圆角（4–8px）、1px 边框、紧凑按钮高度（32–36px）和 12–14px 正文。GPUI 0.2.2 不额外引入阴影组件，层级主要通过背景、边框和间距表达。

## 组件边界

- `src/main.rs`：只负责 GPUI 应用启动、窗口尺寸、无边框标题栏选项和初始刷新。
- `src/ui/main_window.rs`：负责 shell 组合、标题栏、侧栏、内容区路由和窗口控制区域；不改变业务后台操作流程。
- `src/ui/components.rs`：增加标题栏按钮、侧栏导航项、页面 header、卡片、状态徽章等可复用视觉原语。
- `src/theme.rs`：维护框架无关的语义颜色 token；不直接依赖 GPUI。
- `src/i18n.rs`：补充侧栏副标题、页面说明、窗口按钮可访问名称或必要的 UI 文案。
- `src/app.rs`：保持现有状态和业务方法；只在视觉改造需要时增加不改变持久化格式的展示状态。

组件事件统一由 `MainWindow` 的回调触发，并在状态变化后调用 `cx.notify()`。窗口控制按钮使用 GPUI `window_control_area`，不把最小化、最大化和关闭变成 `AppState` 业务事件。

## 保留的功能行为

- 服务列表初始加载、状态刷新、单项启动/停止、全部启动/停止、添加、删除和错误展示不变。
- 添加服务搜索继续按服务名和显示名过滤，支持鼠标选择、添加和取消；文字输入和退格仍可用。
- 系统信息仍异步读取并展示加载、成功和失败状态；点击返回按钮回到工具列表。
- Navicat 清理仍通过脚本页的行或按钮点击启动，并展示结果。
- 设置项点击仍切换语言或主题并保存现有 JSON 格式。
- 四个页面均通过左侧导航点击切换。
- 主页面不恢复任何全局快捷键；窗口关闭使用右上角原生窗口控制区域或系统任务栏/窗口菜单。

## 非目标

- 不实现磁盘清理、网络诊断、进程管理、注册表编辑器和事件查看器。
- 不引入 `gpui-component` 或其他 UI 组件库。
- 不修改业务后端、服务 JSON、设置 JSON 和配置文件位置。
- 不实现自定义窗口阴影、亚克力材质或跨平台独立窗口控制；当前目标平台是 Windows。
- 不用普通点击回调替换 GPUI 原生窗口 hit-test 控制。

## 错误和边界处理

- 窗口控制区域必须覆盖完整按钮 hitbox，且不能被标题栏拖拽区域覆盖。
- 标题栏和侧栏在最小尺寸 `900 × 600` 下仍保持可用；内容区允许滚动。
- 系统信息加载或服务后台任务期间，标题栏和侧栏仍可交互，不能阻塞 GPUI 事件循环。
- 主题切换后标题栏、侧栏、内容背景、边框、按钮和状态徽章必须在同一帧使用新 token 重绘。
- 窗口关闭时不额外写入业务配置，不因后台任务持有窗口强引用而阻止关闭。

## 测试和验收

### 自动化测试

- 保留现有 `AppState`、backend 和 GPUI smoke tests。
- 为主题 token 补充浅色/深色关键语义值测试，避免主色和危险色交换。
- 为窗口壳层补充 GPUI render smoke test，验证标题栏、侧栏和内容区域可以在最小窗口尺寸渲染。
- 若 GPUI 测试平台支持窗口控制区域命中测试，验证 Drag、Min、Max、Close 四类区域均被注册；不支持时至少保持编译覆盖和结构化 id。

### Windows 手工验收

1. 窗口没有系统绘制的默认标题栏，标题栏视觉与页面一致。
2. 拖拽标题栏空白区域可以移动窗口，点击按钮分别最小化、最大化/还原和关闭。
3. 窗口最大化后左侧导航仍保持固定宽度，右侧内容正常伸缩。
4. 四个侧栏导航项可以切换页面，active 状态清晰。
5. 服务按钮、服务行选择、添加服务搜索/选择、系统信息返回、脚本执行、语言和主题切换都可以通过鼠标完成。
6. 服务和系统信息后台操作期间窗口不冻结。
7. 浅色和深色主题下没有低对比度文字、错误状态色或标题栏按钮错位。

## 验收标准

- `MainWindow` 使用“标题栏 + 固定侧栏 + 可伸缩内容区”的布局。
- Windows 默认标题栏隐藏，GPUI 注册 Drag/Min/Max/Close 原生窗口控制区域。
- Element Plus 风格的颜色、间距、圆角和状态语义贯穿两套主题。
- 现有功能和配置兼容性保留，页面操作不依赖全局快捷键。
- `cargo test`、`cargo clippy -- -D warnings`、`cargo build --release` 和 `cargo fmt -- --check` 全部通过。
