# 配置与数据格式

## 配置目录

程序从当前可执行文件路径取得父目录，并在其下使用 `config`：

```text
<程序目录>\config\
```

开发运行时，这通常是 `target\debug\config`；发布二进制运行时，则是发布可执行文件旁的 `config`。日志位于 `config\logs\rust-win-tool.log`。

程序会尽力创建配置目录。若目录不可写，部分保存错误会被忽略，应用仍可能继续运行，但设置、列表或脚本可能无法持久化。建议在更新、搬迁或删除程序前备份整个 `config` 目录。

## `settings.json`

界面语言和主题保存在一个 JSON 对象中：

```json
{
  "language": "zh",
  "theme": "dark"
}
```

| 字段 | 可用值 | 默认值 |
|---|---|---|
| `language` | `zh`（简体中文）、`en`（英文） | `zh` |
| `theme` | `dark`（深色）、`light`（浅色） | `dark` |

文件缺失或内容不能解析时，应用使用默认设置。切换语言或主题时会保存该对象。

## `managed_services.json`

该文件是服务关注列表的 JSON 数组。每项结构如下：

```json
[
  {
    "name": "Spooler",
    "display_name": "Print Spooler",
    "enabled": true
  }
]
```

| 字段 | 含义 |
|---|---|
| `name` | Windows 服务的内部名称，用于查询和控制服务 |
| `display_name` | 面向用户的显示名称 |
| `enabled` | 为兼容既有数据保留；当前管理列表行为不使用该字段筛除服务 |

该文件只保存应用管理的服务名称和显示信息，不保存完整服务配置。导入文件会替换当前列表；如需回滚，请先导出现有列表或复制该文件。

## `scripts.json`

该文件保存用户自定义脚本数组，不包含 UI 中定义的内置 Navicat 和 DNS 操作。示例：

```json
[
  {
    "name": "显示网络配置",
    "kind": "powershell",
    "command": "Get-NetIPConfiguration"
  },
  {
    "name": "列出文件",
    "kind": "cmd",
    "command": "dir C:\\"
  }
]
```

| 字段 | 含义 |
|---|---|
| `name` | UI 中显示的脚本名称 |
| `kind` | `cmd` 或 `powershell`，序列化值为小写 |
| `command` | 要交给对应解释器执行的脚本内容，可包含多行 |

读取时缺少 `kind` 的旧数据默认为 `cmd`，以兼容旧格式。编辑该文件时应保留 JSON 转义规则；更推荐通过应用脚本页增删脚本。

## 日志

```text
config/logs/rust-win-tool.log
```

日志按行追加，记录应用启动及部分操作事件。应用不提供日志轮转配置。删除日志文件前请先退出应用；日志不是完整的安全审计记录。

## 备份与迁移

1. 退出应用。
2. 复制整个 `config` 目录到安全位置。
3. 把程序移动到新目录后，可将备份的 `config` 放到新可执行文件旁。
4. 启动应用并检查语言、主题、服务列表和脚本。

跨版本迁移时应保留原始备份。字段的默认值和兼容规则可能随版本变化；不要手工删除未知字段，除非确认当前版本不再需要它们。
