# 开发与故障排查

## 开发环境和命令

使用 Windows PowerShell 7.6 或更新版本和 Rust 稳定版工具链。从仓库根目录运行：

```powershell
cargo build
cargo run
cargo fmt --check
cargo clippy -- -D warnings
cargo test
```

`cargo run` 会在构建成功后启动桌面程序；查看编译输出时，窗口启动后终端可能保持运行。仅检查构建时可运行 `cargo build`。

## 修改代码时的约定

- 系统信息、服务、注册表、文件扫描和子进程工作放在 GPUI 后台任务中，避免阻塞界面事件循环。
- 为中英文界面添加文案时，同时更新 `src/i18n.rs` 中的中文和英文翻译。
- 修改服务、设置和脚本持久化时，保持既有 JSON 路径及向后兼容规则，或同步编写迁移方案。
- 修改系统操作时，清楚说明权限、确认步骤、可恢复性和跳过失败项目的行为。
- PowerShell 子进程在 Windows 上以隐藏窗口方式运行。
- 不新增全局快捷键；输入处理限于相应的文本编辑控件。
- 修改后应更新 `docs` 中相关中文章节，避免目录、字段和 UI 行为说明过期。

## 常见问题

### 启动时出现 UAC 提示

这是 Windows 启动逻辑的预期行为。应用管理服务、系统目录和本机级启动项，需要相应权限。若取消 UAC，当前程序不会以普通权限继续运行。

### 配置或日志没有保存

数据写在可执行文件旁的 `config` 目录。检查该目录是否可写、磁盘是否可用，以及是否有安全软件拦截。把二进制放在受保护的系统目录可能导致写入失败。先退出程序，再检查文件和权限。

### 清理后仍有文件

被占用、访问被拒绝或需要额外权限的项目会被跳过。扫描结果是估算值，不能保证清理结束后目录为空。不要为了清空目录而手工强制删除正在使用的系统文件。

### Ping 没有结果

当前实现只支持 IPv4 ICMP。目标主机或网络防火墙可能拒绝 ICMP；这不等同于主机上的 TCP 服务不可用，可另外测试目标 TCP 端口。

### 进程名称或端口所有者为空

受保护或权限不足的进程可能无法读取名称。应用拒绝终止 PID 0 和 PID 4；结束其他进程也可能造成数据丢失。

### 服务操作失败

确认服务名称正确、目标服务未被系统策略限制，并检查是否存在依赖关系。启动类型修改、启动和停止都会调用 Windows 服务管理接口；应用不会绕过系统权限错误。

### 自定义脚本执行结果异常

确认脚本类型、命令语法和当前工作目录假设。脚本以应用权限执行，且不是沙箱进程。运行前先逐行审查脚本内容；不要执行来源不明的代码。

## 安全和数据恢复边界

- 清理器只扫描代码定义的固定路径，不接受任意路径输入；遍历不跟随重解析点。
- 永久清理不可撤销；回收站模式可在回收站未清空前尝试恢复。
- 清空回收站会影响回收站内的所有文件，不局限于本应用操作。
- 禁用启动项通过移动到配套位置实现，通常可以从应用中重新启用；手工修改注册表前仍应备份。
- Navicat 操作对 CLSID 候选项尝试备份，但另外两个指定 Navicat 子项直接删除。备份并不保证整个操作可完整回滚。
- 自定义脚本没有沙箱，并可能以提升权限执行。
- `rust-win-tool.log` 是运行日志，不是安全审计日志；公开分享前检查其中的路径和个人信息。

## 反馈问题

报告问题时请尽量说明 Windows 版本、复现步骤、期望行为和实际结果。只附上必要日志，并先删除用户名、目录、机器名等不希望公开的信息。不要上传访问令牌、密码、私钥或其他凭据。
